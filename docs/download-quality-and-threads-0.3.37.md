# 0.3.37 下载画质与自动连接分配

## 行为

保存前使用原有页面请求与本机 WBI 签名通道读取当前视频、分 P 和 DASH 轨道，不读取或导出 Cookie。只列出具有合法媒体地址、且有可用音频轨道的画质；不把 accept_quality 的宣传列表当作可下载列表。默认普通 1080P（qn80），没有时选实际返回的最高画质。表单只新增一个“下载画质”选择项，保留名称、标签和摘要。

用户选定后严格匹配该画质，不能用不同画质替代。轨道地址与画质列表来自同一次返回，提交前核对路由和选区；失败重试重新读取。重试保留用户选择，原选择不可用时回到本次列表的默认值。成品任务标识加入画质，防止相同时间区间的低画质成品被当作新画质重复任务；分片缓存仍按轨道身份、初始化段和索引隔离。

视频连接计划按时长或未缓存大小升级：4（短片）、8（至少60秒或32MiB）、12（至少180秒或96MiB）、16（至少600秒或256MiB）。音频一般1，超过1MiB用2，至少180秒且4MiB用4。实际数量不超过剩余分片数量，也按视频每连接至少约1MiB、音频约256KiB的剩余工作量缩小池。部分缓存先校验长度和SHA-256再参与规划。两个不同视频继续并发，最多40个媒体请求，避免无限连接造成不受控资源占用和重试风暴。

保留暂停、续传、局部有限重试、源一致性检查、慢源切换与精确裁剪；不承诺仅靠增加连接就能恢复真实CDN速度。

## 本地验证

- 完整63项Node回归通过，无跳过。新增画质默认值、过滤非法地址与锁定宣传画质、手选轨道、画质任务身份、长短任务连接规划测试。
- 实际内置Range调度对照：本地生成16个1MiB视频范围、600秒索引和小音频，冷缓存，每请求返回头延迟90ms；四连接与自动16连接分别接收16777576字节，组装输出与预期逐字节一致。传输阶段0.43/0.33秒；部分缓存补充后复测0.44/0.34秒。此为可控响应下的功能与小样本计时，不是实际B站提速比例。
- 78项浏览器模拟页面验收通过：默认1080P、手选720P后提交对应地址、没有1080P时默认最高可下载画质，以及既有暂停、进度、并发与配对交互。
- 完整回归后新增部分缓存预读取，另行4项自动连接、实际Range池和暂停续传复查通过。
