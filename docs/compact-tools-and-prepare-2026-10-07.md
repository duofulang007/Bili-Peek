# 2026-10-07：工具磁盘精简与下载准备并行

本轮沿用 Node 内置下载器，没有新增运行依赖，没有更换媒体编码或裁剪语义。原有用户脚本、全屏界面等未提交改动保留。

## 已采用

1. 音频、视频同时准备初始化段、SIDX、缓存和同轨道来源测速。轨道顺序固定，任一准备失败终止并等待其他请求，不启动新的备用源请求。开发用关键帧分支因音频选区依赖视频实际起点，继续按顺序准备。后续连接规划、字节范围校验、缓存摘要、暂停续传和两任务并发限制不变。
2. 用 Windows 原生 `compact /C /EXE:XPRESS4K` 压缩现用 FFmpeg 和 ffprobe 的磁盘存储。不是替换成删减编码能力的二进制，也不是压缩视频；工具文件内容 SHA-256 不变，没有新增运行依赖。[Microsoft 官方命令说明](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/compact)。
3. 工具安装脚本按 1 MiB 块核对下载包 SHA-256，避免一次读入整个大包。安装后尝试 Windows 原生压缩；文件系统不支持时明确提示，工具仍可使用。安装完成后删除本次生成的下载包，来源和校验记录保留。
4. 测试分片缓存使用 `tests/export-sandbox/segment-cache`，测试清理只处理测试目录。`BILI_PEEK_SEGMENT_CACHE` 为测试注入缓存路径；正常助手仍使用 `.local/segment-cache`。

## 未采用

- Gyan 8.1.2 full-shared：所需程序和 DLL 合计约 253 MiB，比现用两静态工具更大。
- BtbN 9.0 GPL shared：远程 ZIP 目录显示所需程序和 DLL 合计约 182 MiB，收益有限，没有安装。
- UPX：快速级别让两程序逻辑大小合计降至约 90 MiB，但同一完整导出测得 6.95／5.38 秒，原版为 4.32／4.32 秒，启动开销明显，未采用。下载的压缩工具没有留下运行依赖。
- NVIDIA 硬件编码：现用与共享库候选都要求 NVENC API 13.1，当前驱动只提供 13.0，实际编码探针失败。Windows Media Foundation 硬件编码探针也失败。没有修改驱动，没有启用硬件编码配置，试验代码已撤回。
- 没有重写 Rust/curl 下载器，也没有增加无上限连接。
