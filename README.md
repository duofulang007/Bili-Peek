# Bili-Peek

用于 Edge / Tampermonkey 的 B 站视频观看助手。当前版本 **0.3.43**。

视频右侧展示词云与弹幕密度图，支持词语联动、点击定位、观看区间记录和片段选取；配合本地助手，可将带声音的视频片段与字幕原文保存到 Obsidian。无需 AI 服务。

## 安装用户脚本

### 推荐：CPod 固定加载器

先在 CPod 的 Bili-Peek 维护面板点“验证并应用更新”，再打开 `http://127.0.0.1:18767/Bili-Peek-loader.user.js`，在油猴中确认更新一次。加载器沿用原脚本名称和 namespace，替换旧脚本，保留配对与观看记录；不要另建第二份脚本。

以后修改源码，只需在 CPod 点一次更新，再刷新 B 站页面。更新做快速语法和加载器权限兼容检查，完整回归测试留在独立的“运行检查与测试”按钮。助手源码改变且助手正在运行时自动安全重启；正在保存片段时拒绝更新，不中断导出。Obsidian 阅读插件的已安装副本仍需要单独安装。

更新将当前 `Bili-Peek.user.js` 发布为 `.local/runtime.json`，保留上一版 `.local/runtime.previous.json`。加载器从仅监听本机的 18767 端口读取已发布版本，并核对 SHA-256。页面只在刷新时切换，不在播放或保存过程中替换代码；更新服务离线时使用上一次核验过的缓存。源代码修改不会直接进入页面，必须先点 CPod 更新。加载器版本与业务脚本版本分别管理；新增权限时必须重新安装加载器，普通业务修改无需再打开油猴更新页。

### 直接安装（备用）

1. 在 Edge 安装 Tampermonkey。
2. 打开 [Bili-Peek.user.js](Bili-Peek.user.js)，复制全部内容，在 Tampermonkey 中新建脚本并保存。升级时替换旧脚本，避免同时启用两份。
3. 刷新普通 B 站视频页，按提示允许访问 `api.bilibili.com`。

独立观看双图时不需要 Node.js、本地助手或 FFmpeg。双图仅用于普通视频页；B 站首页仅用于接收 CPod 的首次自动连接，不插入面板。不支持直播、番剧和互动视频分支。UP 信息上移，推荐视频保留并下移；两张图与播放器上下边缘对齐，全屏时隐藏。

## 图内操作

- **词云**：切换“高频词 / 重复短语”。点击词语，在密度图中用橙线标出出现时段；再次点击或清除可恢复。候选最多 80 项，实际显示数量随图框大小调整。
- **密度图**：悬停查看时间桶、弹幕数和最多三条不同原文；点击定位视频，保持播放或暂停状态。左右键选择位置，回车跳转。
- **观看记录**：灰蓝细线表示累计实际观看区间，小圆点表示本次起点，虚线表示当前播放位置。暂停、缓冲和跳过部分不计入观看。按视频与分 P 保存在油猴本地数据中，最多保留 200 项。
- **截取选区**：拖动左右把手调整区间，拖动中间整体平移；拖动不改变播放位置。时间框支持秒数、`分:秒` 和 `时:分:秒`，回车或离开输入框应用；悬停滚轮每次调整 1 秒。把手支持左右键，Shift 每次调整 10 秒。
- **保存**：点击保存图标立即打开表单，填写笔记名称、必填标签与选填摘要；画质在后台读取，完成后可提交，读取失败可在表单内重试并保留已填内容。已配对时导出视频与笔记，未配对时仅保存本地选区草稿。单次选区最多 30 分钟。

没有弹幕或关闭弹幕的视频仍可定位、选区和保存。请求失败显示错误与重试，不绘制冒充零弹幕的曲线。切换视频或分 P 会取消旧请求并重置选区。

## 保存到 Obsidian

### 首次配置

需要 Windows、可运行的 Node.js、Python（仅用于下载工具）、FFmpeg 与 ffprobe，以及已有的 Obsidian 仓库。项目没有 npm 依赖。

在项目目录执行：

```powershell
python helper/download-tools.py
node helper/configure.cjs
```

下载脚本从 gyan.dev 获取 FFmpeg Windows essentials，并核对发布方 SHA-256，将工具保存到 `.tools/`。

编辑新建的 `.local/export-config.json`，将 `vault` 改为自己的 Obsidian 仓库绝对路径，`output` 改为仓库内的目标笔记目录，确认 `ffmpeg` 和 `ffprobe` 路径正确。配置脚本内的默认仓库路径属于开发者电脑，其他电脑必须修改；保留随机生成的 `token`，不要公开。

推荐在 CPod 的 Bili-Peek 卡片点击运行：助手在后台启动，不自动打开浏览器或 B 站页面。已配对的网页沿用油猴保存的配对信息；首次使用时，手动打开 B 站视频页，按下方步骤复制配对码并在油猴菜单完成配对。需先安装 0.3.23 或更新版本，并按油猴提示允许本地地址请求。

不用 CPod 时，也可执行 `启动片段助手.cmd`。首次手动配对：

```powershell
node helper/start.cjs
powershell -NoProfile -ExecutionPolicy Bypass -File helper/copy-pairing.ps1
```

在 B 站页面打开油猴菜单“连接片段助手”，粘贴配对码。按提示允许本地地址和字幕域名请求。助手在后台运行，仅监听 `127.0.0.1:18766`，要求配对码，不读取或导出浏览器 Cookie。

项目中的 `启动片段助手.cmd` 是开发者电脑的便捷入口，内含固定 Node 路径；使用前需要改为自己的 `node.exe` 路径。它只启动助手，不自动打开网页。助手重启保留令牌；助手离线时无需重新配对。

### 导出行为

保持 B 站登录，选择区间后保存：

- 生成一条 Markdown 笔记和一个带声音的 MP4，媒体放在目标目录的 `Bili-Peek附件/`，同名笔记增加短编号，不覆盖原文件。
- 保存表单只列出当前可下载的画质，默认 1080P；没有 1080P 时默认最高可下载画质。可手动修改，与播放器画质独立；对应轨道缺失时提示重试，不静默降级。
- 从同一音视频轨道的主地址与备用地址中选择助手允许的 HTTPS 下载地址，保留签名参数；主地址不符合校验时使用该轨道的备用地址，不改变画质。全部地址不受支持时，在提交导出前提示错误。
- 视频重新编码裁剪，核验音视频轨道、可解码性与时长，存在帧率与音频编码粒度容差。只有源轨道证实到达文件末尾且成品通过核验，才允许按实际末尾时长保存并注明。
- 字幕保留原文与相对片段起点的段首时间，合并碎行但不改写、纠错或生成分析。跨选区整句会明确标注；不生成独立 SRT。
- 缺少字幕或区间无字幕时自动保存视频并在笔记注明，不生成假转录。自动语音转录尚未接入。
- 标签支持 `学习/编程` 层级形式；摘要可留空。失败或取消后，在当前页面重存同一区间会恢复表单草稿；成功后清空。

成功任务的阶段计时保存在 `.local/export-timings.jsonl`，不记录配对码或媒体地址。仅在文件写入成功后提示完成，失败会清理已知暂存文件。

### 自动并行下载

0.3.36 起，助手可用时自动采用内置并行下载，无需勾选或额外安装下载器。原 N_m3u8DL-RE 保留用于开发对照；开发诊断配置 `segmentNative: false` 可切回原调度，此时需 `python helper/download-nre.py` 安装锁定且校验过 SHA-256 的官方工具。

下载采用保存表单所选画质的音视频地址，读取初始化段及 SIDX 索引，只请求选区覆盖的分片和解码所需的前置分片；最后精确裁剪并核验成品。源服务器必须返回正确的 206 字节范围；索引缺失、不支持或响应错误时明确失败，不静默下载整条轨道。没有新增浏览器权限，不读取或导出 Cookie。

在有未缓存媒体且存在主备地址时，最多比较三个合法来源。备用源须与当前轨道的初始化段、索引和同范围测速内容一致，每源媒体测速最多 1 MiB、单次读取过程最多 8 秒；测速流量计入接收量。失败的源切换后有限重试；完整分片明显变慢且有测得更快的未试来源时，只切换后续请求，不丢弃正在推进的分片。

0.3.37 内置调度按未缓存字节和片段时长规划连接数：视频短片 4 个，达到 60 秒或 32 MiB 为 8 个，达到 180 秒或 96 MiB 为 12 个，达到 600 秒或 256 MiB 为 16 个。音频超过 1 MiB 用 2 个，达到 4 MiB 且至少 180 秒用 4 个，其余 1 个。连接数还受待下载分片数量与剩余数据量限制；缓存尾段会缩小连接池。两个不同视频可同时处理，最多 40 个媒体请求，不设置无限连接。轨道失败会停止并等待其他请求；保留有限重试、范围校验和 SHA-256 校验。原引擎开发对照路径保留视频四/音频一调度。

未完成分片保存到已有缓存目录，关闭文件后记录已写字节数和 SHA-256；续传先验证大小与摘要，再从剩余字节请求。损坏或超范围部分丢弃重取。主动暂停后进度保留已写部分；真实收到的字节另行统计。连续初始化段与索引合并为一次请求。来源资源连续两次超时/5xx 时短暂冷却三分钟，最多记住 32 项；不同轨道隔离，不记录签名地址，仅在有其他候选时避开失败来源，全部冷却仍保留兜底。

保存流程始终采用精确裁剪，视频编码最多使用八线程（不超过逻辑处理器一半，最低二线程），输入解码和核验限制为二线程。开发接口仍保留关键帧模式和独立文件标识用于对照，用户表单不再提供改变起点的选项。

显示速率采用近三秒真实接收量的平均值，暂停立即显示零；平滑显示本身不会增加吞吐量。计时日志记录准备、传输、组装时间，各轨道用时、请求峰值与有待处理请求但无新数据的采样时间，另保留最终来源域名、有效来源数及切换次数，不记录签名 URL。传输时间包含主动暂停；无数据采样时间不包含暂停。实际吞吐量取决于 CDN 与网络；测速增加少量启动耗时和流量，没有保证任意来源都能提速。

下载阶段可以暂停/继续；暂停终止当前网络请求，继续复用已校验完整或部分分片。进入裁剪与核验后只支持取消，提交文件时不可取消。网页关闭或助手重启后不会自动恢复任务列表，但在新版页面重试同一选区时，源初始化段和索引相同的缓存仍可复用；签名过期需要页面重新获取地址。

网络分片连续 60 秒无数据会终止该请求，下载器重试最多 3 次；下载/转码/核验连续 120 秒无进展会失败。主动暂停不计入停滞时间，没有固定的下载总时限。原方式只有媒体处理进度，没有真实网络速率或暂停续传。

分片缓存保存在 `.local/segment-cache/`，0.3.32 按轨道身份、初始化段和索引区分来源，并按绝对字节位置存分片；同源重叠选区共享已校验分片，避免重复下载。旧缓存未删除，新格式会重新建立。缓存目前没有自动清理或容量上限，会占用磁盘；不包含用户笔记、正式附件、Cookie 或媒体地址。真实 B 站不同编码、长选区、末尾与故障场景仍需验收，当前模拟提速结果不能作为实际网络承诺。

### Obsidian 阅读插件（可选）

配置仓库后执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File helper/install-obsidian-player.ps1
```

脚本将 [obsidian-plugin](obsidian-plugin/) 安装到配置仓库并加入启用列表，随后重新加载 Obsidian。

阅读视图显示上方播放器和下方独立滚动的字幕正文，点击段首时间可跳转本笔记的 MP4，保持播放状态与阅读位置；隐藏重复标题，Markdown 原文不变。仅处理 Bili-Peek 笔记，源码编辑和实时预览暂不支持该布局。

插件运行时，删除片段笔记会检查现存 Markdown、Canvas 与 Base 的引用，将无人引用的 Bili-Peek 视频移入系统回收站。共享视频保留，读取失败则不清理；回收站仍占磁盘空间。

## 数据口径与限制

- 先读取匹配当前视频的页面元数据，必要时请求视频信息，再按当前分 P 的 cid 分段读取弹幕。仅覆盖接口返回的可获取弹幕，不代表全部历史弹幕或全部观众。
- 词频为“提及该词的弹幕条数”，同一条内重复提及只计一次，相同文本的不同弹幕分别计数。排除代码/BAS 与非普通池消息。
- 重复短语是至少两条弹幕提及的连续 2–4 个词，使用浏览器中文分词器与少量专业词补充，不是 jieba 或 AI 总结。
- 密度统计全部已取得且落在当前视频时长内的弹幕，桶宽在图内标注。峰值只反映发言数量，不能单独判断情绪或原因。
- 仅缓存当前分 P，五分钟有效，不写入磁盘；切换分 P 时先释放上一份数据，返回旧分 P 需要重新读取。去重后的弹幕不保留 ID，离开视频页时释放图表与弹幕数据；超过 12 小时或 15 万条弹幕会提示限制。

### 磁盘占用与清理

项目源码很小，主要磁盘占用来自 `.tools/ffmpeg.exe` 与 `.tools/ffprobe.exe`（合计约 201 MiB），保存视频片段和媒体导出测试都需要这两个工具。保留 `.tools/source.txt`，方便追溯下载来源与校验值；工具缺失时可重新运行 `python helper/download-tools.py`。

可按需删除以下可重新生成的文件：

- `.tools/ffmpeg-release-essentials.zip`：工具解压完成后留下的下载包。
- `.local/benchmark-*`：`helper/benchmark-export.cjs` 生成的合成视频；基准结果保存在 `.local/export-benchmark.json`，可单独保留。
- `tests/export-sandbox/`：媒体导出测试生成的临时仓库与视频，后续测试会重新创建。
- `tests/artifacts/`：本地验收截图与录制产物，需要历史验收证据时先另行保存。

不要整目录删除 `.local/`：其中的 `export-config.json`、`browser-paired.json` 等保存助手配置与连接状态。源码、测试脚本、预览资源、设计文档及 Git 历史应保留；日志、诊断与基准结果可用于维护排错。

## ControlPod 项目卡片


项目内的 `.apex/module.json` 提供“Bili-Peek 与片段助手”模块。仓库放在总控台扫描的项目目录（默认 `D:\Projects`）后，完全退出并重新打开 ControlPod，自动出现 **Bili-Peek** 项目卡片。

卡片支持启动、关闭与重启本地助手，复用已有配置和 Node 环境。重复启动不会创建第二个助手；关闭前核对进程身份与健康状态，正在保存片段时拒绝关闭。安装新版脚本并连接后，网页默认跟随助手状态：每 0.25 秒检测一次，首次连接失败后在 0.05 秒后复查，确认离线后立即移除双图并恢复原页面布局；切回页面时立即检测。请求最多等待 0.25 秒；两次请求都超时时，前台页的检测等待上限从 1.85 秒降为 0.8 秒（不含 CPod 关闭动作和浏览器调度开销）。后台标签页可能受浏览器计时限制。再次启动无需刷新即可恢复，不改变播放器的播放位置或暂停状态；首次图表数据加载仍取决于 B 站接口响应。

如需主动打开连接页，可单独执行 `node helper/connect-browser.cjs`。该工具使用两分钟有效、仅能兑换一次的临时凭证，长期配对码不放进浏览器 URL；网页读取后立即清除片段。只有网页用保存的配对码成功访问助手后才记录连接完成。项目启动流程不调用此工具。

油猴菜单仅保留“连接片段助手”和“复制排错信息”。未配对时双图独立运行；配对后统一跟随助手启停，不再提供模式切换，旧版保存的独立运行开关不再生效。卡片不能启用被油猴禁用的脚本，也不会安装油猴；需安装新版本后刷新已有视频页一次。选择 CPod 调度时，不建议同时配置助手登录自启动，否则登录也会启动助手和双图。

可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tests/controlpod-smoke.ps1` 验证实际启动、重复启动与关闭；测试结束恢复助手原来的运行状态。仅在没有片段正在保存时运行。

`node tests/controlpod-pipes.cjs` 额外验证 CPod 重定向输出时，启动任务和输出通道能在后台助手仍运行的情况下结束。适配器用隐藏进程启动 Node，并只等待启动器本身退出，避免助手继承 CPod 输出通道，使启动任务长期悬挂、关闭时需要额外中断。该测试同样恢复助手原运行状态，仅在没有片段正在保存时运行。
