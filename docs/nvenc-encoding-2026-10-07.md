# NVIDIA 编码接入与实测（2026-10-07）

本机 RTX 5060 Ti，当前驱动实测为 617.42。现有 FFmpeg 9.0.2 的 NVENC 单帧探针已成功；沿用已有媒体工具和 Windows 原生压缩，没有新增运行依赖，没有再次修改驱动。

## 实现与启用

`helper/export.cjs` 按本地 `videoEncoder` 配置选择 `libx264` 或 `h264_nvenc`，保持原有精确输入 seek、选区时长、音视频映射、AAC、成品时长/轨道校验和完整解码核验。硬件路径使用 p4、VBR-CQ27、H.264 8-bit 4:2:0、3 个 B 帧；关键帧开发对照路径仍使用 copy。

本机 `.local/export-config.json` 已设置 `videoEncoder: h264_nvenc`、`nvencQuality: 27`，配对码、仓库、输出路径及其他原有配置保留。其他安装默认仍使用软件编码，避免在没有兼容 GPU 的电脑上失败。硬件失败不会自动切换软件编码或制造成功。

随后按用户要求加入视频全 GPU 对照，最终还启用了 `hardwareDecode: true`：视频轨道使用 NVDEC/CUDA 解码，在 GPU 内完成 8-bit 4:2:0 格式转换并直接交给 NVENC，成品的视频逐帧解码核验也使用 GPU。音频仍解码/编码为 AAC，网络下载、容器检查、摘要校验与笔记写入保持原实现。关键帧 copy 对照不走 GPU 解码。

质量参数支持本地调节 1–51；NVENC CQ 与 x264 CRF 不是同一质量标尺。本轮先比较输出再选择默认值。[NVIDIA FFmpeg 指南](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/ffmpeg-with-nvidia-gpu/index.html)。

成功任务和助手健康响应记录所选编码器，便于区别配置与实际执行。已有成品继续去重复用，切换编码器不会覆盖旧视频。若以后降级驱动导致 NVENC 不可用，可将本地 `videoEncoder` 改回 `libx264` 并在无活动导出时重启助手。

## 交错对照

本地合成 1080P/30fps 输入，准确截取 5.1–35.1 秒，调用实际 `exportClip` 全流程；源视频和测试笔记放在项目忽略目录的临时模拟仓库，没有写入用户 Obsidian 仓库。按软件、硬件、硬件、软件顺序执行，SSIM 对照同一源的解码帧，覆盖约 900 帧。

| 编码 | 转码 | 完整解码核验 | 全部导出 | 成品大小 | SSIM |
| --- | ---: | ---: | ---: | ---: | ---: |
| x264 veryfast / CRF20 | 2.82 秒 | 1.19 秒 | 4.04 秒 | 26,297,382 字节 | 0.996035 |
| NVENC p4 / CQ27 | 1.69 秒 | 1.34 秒 | 3.07 秒 | 27,549,911 字节 | 0.995145 |
| NVENC p4 / CQ27 | 1.67 秒 | 1.32 秒 | 3.04 秒 | 27,549,911 字节 | 0.995145 |
| x264 veryfast / CRF20 | 2.81 秒 | 1.21 秒 | 4.05 秒 | 26,297,382 字节 | 0.996035 |

平均转码时间减少约 40.3%，完整导出减少约 24.5%，文件增大约 4.8%。四次成品均约 30.0213 秒并通过完整解码。画质指标接近，但硬件结果略低，不能宣称画质无损或完全相同。没有把这些比例套用成真实 CDN 下载提速。

未采用的参数：p6/CQ20 文件约 54.8 MB、导出约 5.2 秒；p4/CQ24 文件约 37.0 MB、导出约 3.3 秒；p5/CQ27 导出约 4.35 秒。最终选择 p4/CQ27 作为速度和文件占用的折中。

原始记录保留在 `.local/nvenc-benchmark-20261007.json`，其他参数对照记录也保留为 JSON。本轮生成的模拟媒体和候选成品在记录保留后清理。

## 最终边际收益比较

在其他回归结束后重新独立交错测量，输入、画质参数和完整提交流程相同。

| 方案 | 两次转码 | 两次解码核验 | 两次完整导出 |
| --- | --- | --- | --- |
| 全软件 | 2.96 / 2.93 秒 | 1.20 / 1.22 秒 | 4.20 / 4.18 秒 |
| 仅显卡编码 | 1.70 / 1.67 秒 | 1.34 / 1.35 秒 | 3.07 / 3.05 秒 |
| 视频解码、编码、核验均用显卡 | 1.68 / 1.66 秒 | 0.51 / 0.51 秒 | 2.23 / 2.22 秒 |

完整 GPU 的整体均值约 2.225 秒，相对软件的 4.19 秒耗时减少约 46.9%，相对仅显卡编码再减少约 27.3%。额外收益主要来自视频核验；源视频解码对这一样本的转码耗时影响很小。因此采用完整 GPU 视频路径，同时保留 CPU 的音频和文件操作，没有为了“全部用 GPU”重写网络或笔记处理。

四个 GPU 成品（仅编码与完整路径）的 SHA-256 完全一致，均为 27,549,911 字节、SSIM 0.995145；把视频解码和核验移到 GPU 没有额外改变这组样本的成品。相对软件原成品仍有约 4.8% 的大小增加和约 0.00089 的 SSIM 差异，不宣称与软件完全等质。

首次完整 GPU 尝试曾测得 6.34 秒，随后及独立复测约 2.2 秒。额外初始化开销的具体原因没有做底层定位，不保证只出现一次。初次/驱动更新后的冷启动与极短片段可能收益较低，不将热启动结果套用为所有视频的固定速度。

首次 GPU 路径对照、与回归同时进行的中间测量、最终独立测量分别保留为 JSON。最终 `.local/nvenc-benchmark-20261007.json` 包含六次结果和成品 SHA-256。

可重新执行：

```powershell
node helper/benchmark-export.cjs
$env:BILI_PEEK_TEST_NVENC='full'
node --test tests/export.test.cjs
```

基准会生成新的模拟仓库，对照软件、仅显卡编码和完整 GPU 三条路径，不命中既有成品；第一个命令要求本机硬件编码和解码可用。环境变量 `1` 只测 NVENC，`full` 测视频完整 GPU 路径；普通完整回归不要求 NVIDIA GPU。

## 验证与边界

- 语法检查与 68 项 Node 回归通过；最终 p4/CQ27 的实际 GPU 导出测试 10 项通过，包含非关键帧精确裁剪、字幕原文、缺字幕、源末尾、并发同名笔记、去重复用和失败清理。
- 完整 GPU 的 10 项媒体回归也通过，并对损坏的媒体验证 CPU 和 GPU 核验都拒绝保存；原 `-xerror` 与完整解码过程保留。实际 NRE/内置分片对照额外以 GPU 运行，暂停续传、缓存重用、精确首帧与音频内容一致性测试通过（模拟媒体，不是 B 站在线验收）。
- 编码配置校验拒绝未知编码器与非法 CQ；新增测试确认硬件失败只尝试一次，不回退另一编码器、不提交笔记或视频，原始错误保留。
- 本机配置已经更新；临时启动真实助手后，健康接口确认 `ready: true`、`videoEncoder: h264_nvenc`、`hardwareDecode: true`。验收后恢复助手原先的关闭状态，下次正常启动即使用完整 GPU 视频路径。
- 实测没有覆盖真实登录 B 站、浏览器保存流程、用户 Apex 游戏或其他类型视频。没有测量整机 CPU、内存和显存变化，不报告对应降低比例。
- 网络下载实现、选定源画质及并发上限没有变化；应用工具体积没有增加。H.264 编码改变的是保存阶段，不保证视频更小。
