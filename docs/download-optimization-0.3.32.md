# 0.3.32 下载与占用优化

默认分片调度改为 Node 内置有界 Range 工作队列：视频四连接、未缓存音频超过 1 MiB 时双连接，总计最多六个。不启动原来两个 NRE 子进程，不生成其临时媒体副本；保留原引擎配置回退与实际引擎回归，使用共同的范围、缓存与换源保护。分片仍先缓存再流式组装，未实现完全无复制管道。

部分分片在关闭文件后记录长度与 SHA-256，续传验证后从剩余范围请求。测试实际暂停并恢复，观察到请求从 SIDX 分片内部位置继续；组装出的音视频与原方式逐字节一致。来源健康按域名与路径摘要隔离，避免音频错误使同域视频被冷却；仅保留最多 32 条三分钟状态，不保存签名 URL。连续初始化段和索引合并请求，完整缓存重试只需两轨道各一次元数据请求。

缓存 v2 改为按同一源轨道身份与元数据区分、按绝对字节位置命名。重叠区间测试第二次只读取两次元数据，不重复读取媒体；输出逐字节匹配新选区对应的源片段。原格式缓存保留，没有清理用户数据。

原调度与内置调度使用相同生成媒体、冷缓存和每请求 120ms/4096 字节的响应，按原、内置、内置、原交错运行。

| 调度 | 两次下载阶段耗时 | 每次收到字节 |
| --- | --- | --- |
| 原 NRE 并行 | 2.447 / 2.467 秒 | 164098 |
| 内置直接并行 | 2.394 / 2.390 秒 | 164098 |

此小样本条件约减少 2.6%，不代表真实 CDN 的固定提速。此前 0.3.31 的串行/并行对照与本表不同；当前测速命令仍为 `$env:BILI_PEEK_SEGMENT_BENCHMARK='1'; node --test tests/segment-download.test.cjs`，现在测原引擎/内置调度。普通回归会覆盖忽略的原始 JSON，本文保留测量。

精确裁剪限制解码二线程、视频编码最多八线程，完整解码核验二线程。独立资源对照使用本地 1080P/30fps/12 秒的已编码视频，相同 libx264 veryfast/CRF20，双线程解码，按自动编码、八线程、八线程、自动交错运行。

| 编码设置 | 两次耗时 | 采样工作集峰值 | 进程线程峰值 |
| --- | --- | --- | --- |
| 自动 | 1.020 / 0.874 秒 | 666.8 / 663.7 MiB | 45 |
| 八线程 | 1.277 / 1.207 秒 | 361.6 / 362.5 MiB | 23 |

该编码测试采样内存约下降 46%，耗时约增加 31%；不是完整导出与整机资源承诺。源与输出均本地生成，未更改用户成品。原始测量保留在忽略目录 `.local/media-resource-probe/results.json`，历史四线程测量另见 Bili23 调查记录，JSON 会被新测覆盖。

新增默认关闭的关键帧快速截取：使用 copy，实际起点提前至视频 SAP；音频按此起点重新选分片，字幕时间基准一致，笔记明确记录实际范围。实测非关键帧选区输出通过时长、轨道与完整解码检查，首帧摘要与源关键帧一致，音视频起点差小于 80ms。精确与快速模式文件标识不同，防止误复用不同精度成品。

尚需真实已安装脚本、新区间冷缓存验证：持续吞吐、音频尾段、签名失效、长任务、不同编码与线程限制的实际峰值占用。
